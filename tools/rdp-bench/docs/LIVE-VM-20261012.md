# Mac M4 / UTM Windows baseline, 12 October 2026

The actual Windows VM campaign uses the production SDL client, a local Edge
fixture, pinned TLS, CRC-valid visual markers and numbered keyboard probes.
The VM is Windows 11 Pro ARM64 build 26200, with four cores and 4 GiB RAM.
Edge 155.0.4283.45 runs in interactive session 2. The external M27UP desktop
is 3840×2160; the browser viewport is 3840×2117, DPR 1.

Both variants use the common TLS receive fix committed in `c4efb1fae`.
The reference starts at `a01c6f6dc`; the candidate starts at `1f4e6441a`.
Frozen build receipts explicitly record the common production patch and
matching libraries. Normal 32 KiB queue and 31-packet local window defaults
remain unchanged. These mostly inbound graphics workloads do not directly
exercise the outgoing bulk path tested by the transport-only campaign.

## Method and retained evidence

Five seeds (11, 29, 47, 71, 101), canvas motion and text scrolling, both
`ten_mbit_clean` and `ten_mbit`, two clients, 5-second warmup and 60-second
measurement, 30 Hz source, 2 Hz probes and a 3-second response drain.
Each trial has fresh private certificate storage and an observed SHA256 pin.
Probe events target only the owned foreground client.

The relay shapes UDP at 10 Mbit/s including IPv4/UDP overhead; TCP control
and fallback are unshaped. This is a UDP impairment campaign. Live traffic
and texture-upload byte rates are not verified application goodput.
Input latency ends at the compositor capture callback, not physical photons.
Whole-trial p95/p99 values are never pooled into a new percentile.

All four TLS-fixed smoke trials completed, returning 80/80 probes. All four
captures authenticate and contain Graphics DVC messages over UDP, channel 7.
The strict ACK classifier preserves Windows packets with unknown bit 0x200
as unclassified. Whole-trial graphics transport is independently proved;
exact measurement-window attribution remains unknown.

The first main attempt contains 40 planned trial rows: 17 COMPLETE, five
response FAIL and 18 INCOMPLETE. Twenty-two measured trials recorded
2640 scheduled opportunities, 2638 injections, 2632 visible responses,
six timeouts and two missed injections. One Windows-agent start command
timed out. The external display subsequently disappeared: one connected
trial reports ScreenCaptureKit error -3815, and 16 later clients explicitly
rejected the unavailable selected display. These failures are preserved.

## Calibration and next work

The unchanged twelve-sample VM echo calibration of the revised relay passed
six strict checks. All CRC, byte/datagram, seeded-drop and ledger audits
passed: 27390 sent, 27382 VM receipts and 27360 exact echoes. Fourteen
seeded drops and 16 reverse queue drops explain the 30 misses. Large host
selector scheduling gaps remain explicit; there is no accepted calibration
receipt. Echo goodput is separate from RDP goodput.

Keep the production queue default. Retain the TLS drain fix: authenticated
regressions and actual VM graphics establish its functional benefit. Improve
relay scheduling isolation and obtain an accepted calibration before tuning
queues from live tails. A full-RDP 10 Mbit/s claim also requires TCP shaping.
Measure idle input and sustained graphics separately to locate the remaining
latency between server frame production, transport, decode, rendering and
capture. The current live data does not establish which layer dominates.

Raw private evidence is under `build/live-vm-bench-20261012/`, including
frozen sources/builds, per-trial journals, captures and matching TLS keys.
The derived report and offline dashboard include metadata and failures,
with no TLS keys or decrypted graphics payloads.

Postcapture validation fully authenticated 17 of the 22 measured captures:
154982 TLS records, 64652 Graphics messages and 27281 matching frame IDs.
Five captures remain unvalidated by the strict extractor (four ClientHello
selection errors and one incomplete final Graphics fragment). Counts cover
whole captured streams before relay impairment; they do not prove exact
client delivery or precise measurement-window attribution. The public
metadata summary preserves those limitations and all original failures.

The selected-display guard now checks a read-only active UUID/ID inventory
before every trial. A globally unlocked desktop cannot substitute another
monitor for the calibrated M27UP. Missing or ambiguous inventory stops new
launches while preserving the remaining planned rows as incomplete.
174 benchmark Python regressions passed after this guard and final report changes; authenticated
native TLS tests and isolated negative controls are recorded separately.

Lock release, bounded exhaustion and read-only denial tests passed; the
ACL-only denial fixture remains explicitly unsupported, without a pass claim.
Updated sources were hash-verified and loaded by a fresh interactive agent.

The observer now returns read-only foreground status. The controller confirms
the exact owned PID before preflight and measurement, with a three-second
